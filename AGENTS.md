# Правила разработки

- Работайте в отдельной ветке от актуальной `main`; не объединяйте и не публикуйте релиз без согласования.
- Не храните в репозитории секреты, PIN, токены и данные игроков. Не меняйте VPS, базы, аккаунты или рейтинг без явного разрешения.
- Не выполняйте платные API-вызовы. Внешние действия и изменения инфраструктуры согласовывайте с владельцем.
- Перед изменениями изучайте код и тесты; сохраняйте совместимость существующих режимов. Запускайте `npm test`, `npm run validate`, `npm run validate:exercises` и соответствующие Python-тесты; сообщайте об ограничениях среды и сбоях.
- Фиксируйте изменения коммитами и в отчёте указывайте проверенные сценарии, команды, результаты и оставшиеся проблемы.

## Общая дисциплина AI VPS

- Перед ручными SSH-командами, пересылкой архивов или просьбой к владельцу собрать диагностику сначала проверь доступные MCP `admin_*`, GitHub и другие подключённые инструменты. Если действие безопасно выполнимо агентом в пределах полномочий — выполни самостоятельно; если нет, объясни точный блокер и минимальное действие владельца.
- При работе с AI VPS используй BookStack 201 как краткий индекс и страницу 133 для ориентира. Применяй релевантные утверждённые оригиналы 139/142/137/136/135/138/145/159/160/190; при расхождении оригинал имеет приоритет. Не перечитывай всё без необходимости.
- Соблюдай RULE047: выбирай минимально достаточный Chat/Work/Codex и усилие, а итог завершай блоком «Следующее действие» (режим, усилие, задача, обоснование, переход, блокер, действие пользователя). Не утверждай, что выполнил проверку или передачу, без фактического результата.
- Для веб-UI Roma Transcriber при наличии доступа к Work и браузеру выполняй реальную браузерную приёмку; не объявляй PASS по одним лишь локальным тестам. Это правило не даёт доступа к другим проектам и не расширяет production-полномочия.
