# Учебный прогресс: SQLite на текущем VPS

Версия 0.3 добавляет опциональную БД `/var/lib/chess-ranking/learning.sqlite` рядом с прежним `players.json`. JSON имён, солей/PIN-хешей, сессий, результатов и звёзд не мигрируется. При переносе на другой хост сохранить оба хранилища; переносить при остановленном сервисе и сохранять права 0700/0600. Не помещать их в GitHub или папку Pages.

SQLite использует встроенный `node:sqlite`, проверено на Node24. Режим JSON без `LEARNING_FILE` остаётся доступен без SQLite. Таблицы хранят результаты отдельно для UUID профиля, с флагами помощи/самостоятельного решения. Версия содержимого1, известный каталог92позиций (28прежних +64начального курса), не более50событий и16KiB в запросе. Идемпотентные события ограничены10000на игрока; база ограничена16384страницами SQLite (при создаваемом размере страницы4096 —64MiB). История нажатий не сохраняется. Звёзды через учебный API не начисляются.

API:
- `GET /capabilities` — публично `{learning:{enabled,contentVersion:1,contentGroups:["beginner-v1"]}} (пустой contentGroups при выключенном обучении)`.
- `GET /learning` — существующий Bearer, `{learning:{version:1,achievements,completed}}`.
- `POST /learning/events` — Bearer, `{events:[{eventId,contentVersion,lessonId,exerciseId,skillId,assistance}]}`; ответ `{learning,accepted}`.

Браузер проверяет capability, затем объединяет завершённые достижения. Локальные факты служат повторяемой очередью при отсутствии сети; стабильные ID не дают повторных наград. Незавершённое занятие и его помощь остаются в слоте текущего устройства. Гостевые данные автоматически не переносятся в вошедший профиль. Полные партии и серверные активные слоты ещё не добавлены.

## Обновление существующего сервиса

`upgrade-learning.py` рассчитан только на проверенный сервис `chess-ranking.service` с Node `/opt/roma-autonomy/node-runtime/bin/node`, loopback8787 и существующим Funnel10000. Скрипт закреплённого релиза нужно проверить по SHA256 до запуска. Затем передать полный `--source-commit` и `--source-sha256` файла backend/server.mjs. Без `--apply` выполняются только проверки и загрузка исходника для проверки, без изменения службы.

При `--apply` скрипт останавливает только эту службу, сохраняет резервную копию JSON/старого кода/unit в `/var/backups/chess-ranking/<UTC>`, заменяет код атомарно и создаёт `/etc/systemd/system/chess-ranking.service.d/50-learning.conf` с LEARNING_FILE. После старта проверяет локальный рейтинг и объявленную SQLite capability. Ошибка запуска вызывает попытку восстановления старого кода/drop-in и запуска прежнего сервиса. Данные игроков при откате не перезаписываются. Старую JSON-копию нельзя автоматически возвращать поверх новых результатов.

Скрипт **не запускает старый установщик**, не меняет Tailscale, firewall, Caddy, приватные443/8443 или публичный10000. Конфликт версии, пути или override вызывает отказ. После аварийного завершения не удалять lock-файлы автоматически: сначала проверить, что процесс действительно остановлен.

Успех локальных проверок не равен проверке публичного HTTPS. После обновления проверить `https://roma-vps.tailcc6aea.ts.net:10000/capabilities` и существующий рейтинг снаружи, затем имя/PIN и учебные достижения на двух реальных устройствах. Автотест с двумя клиентами не заменяет эту приёмку.

## Расширение каталога: начальный курс

Добавлен признак `learning.contentGroups: ["beginner-v1"]`, без изменения contentVersion и схемы SQLite. Старые клиенты продолжают отправлять прежние ID. Новые отправляют 64 новых ID только при наличии этой группы; сервер без группы продолжает принимать прежние три урока. Поле отсутствует/не массив — новые факты остаются локально, синхронизация прежних фактов не блокируется. Поэтапная доставка допускает обновление браузера до сервера. Локальные стабильные события пересылаются повторно после обрыва сети; одинаковые eventId не создают дублей. Продолжение незаконченного занятия остаётся на устройстве. Гости остаются локальными. Оба признака помощи сохраняются независимо.

Для уже включённого SQLite использовать **`ops/upgrade-beginner.py`**, не `upgrade-learning.py` и не fresh-installer. Он принимает только прежний известный SHA256 backend (f5205aba67a4f5c2e9d4be3f2fdb332eace1ad1611ffea78f57099f1beaf556c) или указанный целевой SHA256, требует прежний точный drop-in и параметры unit. Запускать проверенный по SHA256 скрипт из закреплённого commit с `--source-commit FULL_SHA --source-sha256 BACKEND_SHA256`; без `--apply` — проверка, с `--apply` — обновление.

Перед заменой кода служба остановлена; в приватную резервную папку копируются `players.json`, **`learning.sqlite`**, прежний код, unit и drop-in. Существующие unit/drop-in/схема БД не меняются. Ошибка health-check откатывает код и запускает прежнюю версию. Данные при автоматическом откате не перезаписываются: это сохраняет результаты, принятые в короткое время после запуска. Новые факты в SQLite при старом backend временно не выдаются, но остаются в БД и в очереди нового браузера. Резервная копия нужна для отдельного ручного восстановления, а не автоматического затирания свежих данных.

После обновления нужен публичный `GET /capabilities` с beginner-v1, затем проверка переноса новых достижений после входа под тем же именем/PIN на двух устройствах. Одно лишь сообщение updater подтверждает локальные проверки, не публичную и не детскую приёмку. Новая озвучка не добавляется: начальные главы остаются с текстовыми подсказками.
