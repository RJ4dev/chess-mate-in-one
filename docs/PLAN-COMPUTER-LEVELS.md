## Решение

Сохраняем chess.js как единственный источник допустимых ходов. Внешний движок/API увеличил бы объём и мобильную нагрузку; задержки или только случайность не дадут четырёх осмысленных уровней. Выбираем четыре политики на существующем интерфейсе chooseComputerMove(fen, options):

- beginner — «Новичок — 5+»: воспроизводимый случайный допустимый ход, тихие ходы вероятнее взятий; не ищет угрозы, может упускать мат и материал.
- student — «Ученик»: один полуход, материал/развитие и штраф за атакованную незащищённую фигуру (треть её стоимости), ограниченная воспроизводимая ошибка оценки; видит непосредственное взятие/мат, не рассчитывает ответ.
- experienced — «Опытный»: два полухода, защита от немедленного ответного взятия.
- master — «Мастер»: итеративный alpha-beta до трёх полуходов, продолжение взятий на горизонте; сильнейший режим этой реализации, не заявление об Elo.

Бюджеты конечны; каждые несколько узлов поиск уступает UI и проверяет отмену. Незавершённая итерация не заменяет результат последней полной. Семя и порядок ходов воспроизводимы. Диагностика nodes/depth/yields доступна через объект stats, не через UI. Настройка computerLevel в существующем локальном preference key; старые настройки переходят в student. Она относится к устройству, не синхронизируется как достижение. Смена уровня отменяет старый расчёт; после закрытия настроек ход рассчитывается новым уровнем. Сохранения партий, профили и capabilities не меняются. PR26 shared animation/pause сохраняются.

## План / проверяемые результаты

1. Node RED→GREEN: четыре политики, законность/мат/пат/шах/рокировка/превращение/en passant, воспроизводимость, ограничение работы, отмена и сила на фиксированных тактических позициях (доказывает фактические различия).
2. Node RED→GREEN для defaults/normalization/roundtrip; выбор в настройках и подпись режима. Browser: все уровни/reload, настоящий ответ компьютера, смена уровня во время расчёта, сохранённая партия/профиль/ачивки, старые настройки, мобильная геометрия (совместимость).
3. Воспроизводимый скрипт сравнений: фиксированные позиции/семена и парные партии со сменой цветов, отчёт с фактическими результатами и пределами измерений. Не утверждать вероятность победы ребёнка; CPU измерить только для текущей среды, Android подтвердить отдельно.
4. Обе сборки, полный CI, независимый read-only обзор; исправления Important через RED→GREEN; GitHub PR и связанная BookStack запись с точными SHA/ограничениями. Остановка перед слиянием.

Проверить: окончание лимита посреди корневой итерации; отмена во время yield; шах на горизонте; смена настроек/профиля при чёрном ходе; default старых настроек без потери прогресса. Физическая приёмка новой силы Android остаётся открытой до публикации и фактического подтверждения владельцем.
